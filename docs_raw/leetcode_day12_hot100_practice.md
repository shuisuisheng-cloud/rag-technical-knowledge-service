# 题 1：LeetCode 1. 两数之和

## 源码

历史源码：

`leetcode/02_hash/day05_two_sum.py`

Day 12 复测源码：

`leetcode/02_hash/day12_two_sum_retest.py`

## 题意摘要

给定整数数组 nums 和目标值 target，找到两个不同位置的元素，使其和等于 target，并输出两个下标。

## 我的实际完成情况

这是历史题无提示复测。

开始时没有独立回忆起原先的哈希表优化方案，而是自己先提出双层循环暴力枚举。

暴力方案：

- 外层遍历数组，选择第一个元素。
- 计算另一个需要的数字：`target - num`。
- 内层从当前下标之后开始查找。
- 找到后输出两个下标。

初版暴露的问题：

1. 内层从当前下标开始，可能重复使用同一个元素。
2. 使用 `<= n` 可能导致数组越界。
3. `enumerate()` 返回的下标与元素值顺序写反。
4. 循环边界和变量含义需要修正。

这些错误经 ChatGPT 指出后修正。

## 本地验证

三组本地样例通过：

- `[2, 7, 11, 15]`，target=9 → `0 1`
- `[3, 2, 4]`，target=6 → `1 2`
- `[3, 3]`，target=6 → `0 1`

仅确认上述本地样例，不代表在线 OJ Accepted。

## 暴力解复杂度

时间复杂度：`O(n²)`。

因为外层选择一个元素，内层最多再检查剩余元素。

查找过程额外空间复杂度：`O(1)`。

当前完整程序使用 nums 列表保存输入，因此包含输入存储时整体空间为 `O(n)`。

## 哈希表知识复习

ChatGPT 后续讲解了如何使用字典保存已经扫描过的数字及其下标。

字典的映射关系是：

`数字 → 下标`

例如：

`seen[2] = 0`

表示数字 2 对应下标 0。

Python 字典根据键查询，平均时间复杂度为 `O(1)`，因此可以减少重复扫描。

但需要特别注意：

**我只是理解了讲解，并没有在本次独立写出哈希优化代码。**

不能把理解哈希表原理记录成独立实现了 O(n) 解法。

# 题 2：LeetCode 121. 买卖股票的最佳时机

## 源码

`leetcode/01_array/day12_best_time_stock.py`

## 题意摘要

给定每天的股票价格，只能选择一天买入、未来一天卖出。

求最多能获得的利润。如果不存在正利润，则输出 0。

必须满足：

**先买入，后卖出。**

## 第一阶段：暴力解

这道题是首次训练的新题。

自己先想到枚举所有可能的买入和卖出日期。

基本思路：

- 外层选择买入日期。
- 内层检查买入日期之后的卖出日期。
- 计算卖出价格减去买入价格。
- 更新最大利润。

初版出现：

- 输入读取使用 strip 而不是 split。
- 混淆数组下标与元素值。
- while 判断变量错误。
- 内层指针没有正确前进。
- 最大利润初始值及无利润情况处理需要修正。

在 ChatGPT 指出问题后自行完成修正。

暴力版本通过四组本地样例。

复杂度：

- 时间：`O(n²)`
- 查找额外空间：`O(1)`

## 第二阶段：O(n) 优化

ChatGPT 明确讲解了使用历史最低价格优化的方法。

本次优化并非完全无提示独立发现。

核心状态：

`min_price`：截至当前日期见过的最低股票价格。

`max_profit`：截至当前日期能够得到的最大非负利润。

遍历过程中：

- 更新历史最低价格。
- 计算当前价格与最低价格之差。
- 如果利润更大，更新 max_profit。

这样不必反复遍历之前的日期。

我自己根据讲解写出了一次遍历版本。

## 优化过程中出现的错误

最初写成：

`min_price = float('-inf')`

这表示负无穷，不适合用于寻找最小股票价格。

因为任意正常股票价格都不会小于负无穷。

经 ChatGPT 指出后修改为：

`min_price = float('inf')`

表示正无穷。

此后历史最低价可以正常更新。

## 为什么不会违反先买后卖

如果当天价格创造了新的最低值：

`min_price = 当天价格`

此时当天计算出的利润为 0。

严格来说，同一天买入又卖出不是有效的正利润交易，但这个零利润候选不会提高 max_profit。

真正产生正利润的情况，仍然对应以前买入、之后卖出。

## O(n) 版本复杂度

时间复杂度：`O(n)`。

因为只遍历数组一次，每次进行常数数量的比较和赋值。

查找额外空间复杂度：`O(1)`。

如果把输入列表也算进去，当前完整程序的空间为 `O(n)`。

## 本地验证

优化版本确认通过四组测试：

- `[7, 1, 5, 3, 6, 4]` → 5
- `[7, 6, 4, 3, 1]` → 0
- `[2, 4, 1]` → 2
- `[5]` → 0

这只证明有限本地样例通过，不等于在线 OJ AC。

## 简单面试知识：贪心算法

贪心算法通常在每一步选择当前有利的局部方案，并要求这种选择具有得到全局最优结果的依据。

本题可以从卖出日期考虑：

对于确定的卖出日期，之前价格最低的买入日期可以获得最高利润。

因此只需要维护此前见过的最低价格，而不需要重复枚举。

## 循环不变量

每次处理完当天价格后：

- min_price 是截至当天的最低价格。
- max_profit 是截至当天可以得到的最大非负利润。

这两个状态是证明算法正确性的基础。

# 题 3：LeetCode 169. 多数元素

## 源码

`leetcode/01_array/day12_majority_element.py`

## 题意摘要

给定整数数组，保证存在一个出现次数严格大于 n/2 的元素。

要求输出这个元素。

## 我的实际完成情况

这是一道新题。

本次自行想到使用 Python 字典统计数字出现次数。

核心计数结构独立写出：

- 如果数字第一次出现，将次数设为 1。
- 如果数字已经存在，次数加 1。

通过这种方式得到：

`seen = {数字: 出现次数}`

这一部分是自己完成的。

## 初版出现的问题

第一，读取数组时使用了 strip 而不是 split。

第二，最初使用：

`max(seen.values())`

但它只能返回最大的出现次数，不能返回对应的元素。

例如：

`seen = {3: 2, 2: 1}`

`max(seen.values())` 返回 2。

而题目需要输出的是 3。

## 外部 AI 使用记录

因为不知道如何找到“字典中最大值对应的键”，本次主动咨询了另一个 AI。

获得并使用：

`max(seen, key=seen.get)`

这个用法不是独立回忆出来的，必须保留外部 AI 辅助事实。

它的含义是：

- 遍历字典的键。
- 使用 seen.get 查询每个键对应的出现次数。
- 按出现次数比较。
- 返回次数最大对应的键。

例如：

`seen = {5: 3, 8: 2, 10: 1}`

返回 5。

本人在复盘时能够解释为什么返回 5。

## 本地验证

四组测试通过：

- `[3, 2, 3]` → 3
- `[2, 2, 1, 1, 1, 2, 2]` → 2
- `[-1, 2, -1, -1, 3]` → -1
- `[5]` → 5

## 复杂度

时间复杂度：平均 `O(n)`。

原因：

- 遍历数组计数，平均 O(n)。
- 字典查询与更新平均 O(1)。
- 遍历字典寻找最大次数对应的键，最多 O(n)。

额外空间复杂度：`O(n)`。

字典最坏需要保存 n 个不同元素及其次数。

# Day 12 Python 易错点

## 1. enumerate() 返回顺序

正确写法：

`for index, value in enumerate(nums):`

先返回下标，再返回元素值。

不能把元素值误当成下标访问数组。

## 2. strip() 与 split()

`strip()` 删除字符串首尾空白，不会按空格拆分数字。

`split()` 才会把一整行按空白分成多个字符串。

读取整数数组常用：

`list(map(int, sys.stdin.readline().split()))`

本次两数之和、股票题和多数元素中都暴露过输入/API 方面的问题，需要持续巩固。

## 3. 字典的键与值

`seen.values()` 返回值集合视图。

`max(seen.values())` 找到的是最大值。

`max(seen, key=seen.get)` 返回的是对应值最大的键。

不能混淆“数字本身”和“数字出现的次数”。

## 4. 字典查找与列表搜索

列表按元素值搜索通常为 O(n)。

字典按键查询平均为 O(1)。

但字典需要额外保存键和值，可能使用 O(n) 空间。

## 5. float('inf') 与 float('-inf')

`float('inf')` 是正无穷，常用于初始化待寻找的最小值。

`float('-inf')` 是负无穷，常用于初始化待寻找的最大值。

初始化时必须理解比较条件，不能机械套用。

## 6. 时间复杂度与空间复杂度

要区分：

- 查找算法的额外空间。
- 包含输入列表的完整程序空间。
- 一次遍历与双层遍历。
- 字典平均时间复杂度与最坏情况。
